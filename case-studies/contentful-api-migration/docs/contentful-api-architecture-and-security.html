1Executive overview

API.Contentful is a greenfield .NET 10 Minimal API that replaces the legacy Legacy.CMS service. The legacy service read content from Contentful via GraphQL (with AutoMapper, a dynamic query builder, and generated .graphql documents); this rewrite reads the same content from the Contentful REST Content Delivery / Preview API (CDA/CPA) and re-projects it through a small, convention-driven mapping engine.

The golden rule of the project is a byte-for-byte compatible public contract: the same routes, the same CMSAPIResponse JSON envelope, the same PascalCase property names, the same HTML-escaped rich-text output. Correctness is proven by an additive parity + snapshot test suite rather than by inspection.

Access model: the API is anonymous public-read. The earlier preview API-key authentication (X-Preview-Api-Key + [Authorize]) has been removed — Program.cs wires no authentication or authorization middleware. Preview traffic (isPreview=true) is bounded by an origin allow-list (PreviewOriginMiddleware), not by authentication. This intentionally avoids re-introducing a production incident that the legacy team hit and reverted when a preview auth gate rejected legitimate anonymous traffic.

2.3 · The mapping engine (Infrastructure/Mapping + Contentful)

The heart of the service is a small, reflection-based, attribute-driven mapper that replaces the legacy GraphQL + AutoMapper stack. It is convention-first: a DTO property maps from the Contentful field of the same (camelCased) name unless an attribute says otherwise.

  • EntryMapper builds a MappingPlan once per DTO Type and caches it in a ConcurrentDictionary<Type, MappingPlan>; each plan is a list of compiled PropertyPlan entries (a PropertyKind + a compiled setter delegate). Reflection cost is paid only on first use.
  • PropertyKind (verified enum): Ignore, ScalarLike, MapEach, Collection, Complex — the five ways a property value is produced from a ResolvedEntry.
  • The 8 mapping attributes (all present under Contracts/Mapping/): [ContentType], [ContentfulField], [RichText], [Collection], [MapEach], [ProjectFrom], [AssetFlatten], [MapperIgnore].
  • EntryGraphResolver parses a raw CDA response (items + includes.Entry / includes.Asset) into an EntryGraph — an id-keyed index of ResolvedEntry / ResolvedAsset — so links resolve by lookup instead of re-fetching.
  • Cycle & depth safety: recursion is guarded by an ancestor-id set (MapContext) plus a configurable MaxDepth (MappingOptions.MaxDepth = 64). Genuine back-edges are dropped; ordinary shared references map fully.
  • RichTextRenderer renders a Contentful rich-text document JsonElement to HTML, a behaviour-preserving port of the legacy ContentfulRichTextHelper — Task 08 diffs it byte-for-byte.
  • ContentTypeRegistry is built once at startup by reflecting over the Contracts assembly. It is keyed by (targetInterface, contentTypeId) — not a flat map — because e.g. content type image resolves to ImageDto for IMedia but ImageCardDto for ICard.
Two separate maps (kept deliberately straight): an input map contentTypeId → DtoType (from [ContentType], ~60 registrations) picks the concrete type to construct; an output map DtoType → kind (from [JsonDerivedType], ~62 discriminators) supplies the JSON discriminator the frontend switches on.

2.4 · Polymorphism

ISection / ICard / IMedia carry [JsonPolymorphic(TypeDiscriminatorPropertyName = "Kind")] with a [JsonDerivedType] per concrete implementation. System.Text.Json injects the discriminator whenever a value is serialized through the interface type. The quirky discriminator string values (e.g. legalSection, speackerSchedule, stackedCardsSection, Table) are part of the contract and are emitted verbatim by the copied attributes — STJ owns the discriminator slot; the mapper only picks the concrete type.

2.5 · Provider & gateway (resilience)

  • ContentfulRestClient uses two named HttpClients (contentful-rest-delivery / contentful-rest-preview), each with base address, bearer auth, and the standard resilience handler, selected by the preview flag.
  • ContentfulRestContentProvider performs the per-domain fetch → resolve → map pipeline. For per-slug page lookups it fans out concurrently across the 8 page content types in a fixed precedence order (a content-type-less fields.slug filter is rejected by Contentful with HTTP 400, so fan-out is the only viable approach).
  • ContentGateway implements the fallback-only caching flow with Polly v8:
    • A gateway-level circuit breaker (outer) wraps a per-request timeout (inner); when open, Contentful is skipped entirely and the fallback cache is served.
    • A per-key single-flight coordinator coalesces concurrent identical requests into one upstream call (thundering-herd protection).
    • Successful fetches are written to the fallback cache fire-and-forget, throttled to at most one write per key per interval.
    • On failure with no cached value, it throws ContentUnavailableException, which the endpoint layer maps to 503.
    • Preview is never cached (not read, not written); preview fetch failures return default.
  • Fallback store: IFallbackCacheStore with an in-process default (InMemoryFallbackCacheStore). A Memcached swap-in path is documented but not wired in this environment.
  • SlugAllowList bounds which slugs can reach Contentful: a volatile HashSet<string> per scope (Page / Blog / Article), atomically swapped on reload, fail-open on the first load only, refreshed by SlugAllowListReconcileService (default 15 min) and the webhook.

2.7 · Cross-cutting concerns

2.8 · Serialization contract

Configured once via ConfigureHttpJsonOptions in Program.cs, to match legacy byte-for-byte:

SettingValueEffect
PropertyNamingPolicynullPascalCase property names (C# member casing preserved)
DefaultIgnoreConditionNevernulls are written (not omitted)
EncoderJavaScriptEncoder.DefaultHTML-escaping encoder (<p> → \u003Cp\u003E), matching legacy
These three settings reverse the Minimal-API defaults (camelCase / relaxed encoder) on purpose. The legacy service serialized every response body through a default JsonSerializerOptions written by a custom ActionResult that bypassed the MVC AddJsonOptions(camelCase) config — so the real wire contract is PascalCase with nulls written. The exception middleware reuses the same options, so error bodies match too.
