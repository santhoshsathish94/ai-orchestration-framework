5. OWASP Top 10 (2021) assessment

CategoryStatusNotes
A01 Broken Access ControlOKPublic-read CMS content API (anonymous by design, matching legacy). Unknown slug ⇒ 404 with no upstream call (slug allow-list). Preview (isPreview=true) restricted to configured origins (preview.example.com). Webhook requires shared-secret + HMAC.
A02 Cryptographic FailuresOKNo secrets in code; HTTPS enforced (EnableForHttps); webhook uses HMAC signature verification.
A03 InjectionOKNo SQL. Contentful queries use structured parameters. Content originates from the trusted Contentful CMS (not end users). JSON output uses the default HTML-escaping encoder.
A04 Insecure DesignOKFallback-only cache with circuit breaker + single-flight (thundering-herd protection); preview never cached.
A05 Security MisconfigurationOKCORS limited to configured origins (GET/OPTIONS only); forwarded headers trusted from the ingress only; global exception handler returns a structured CMSAPIResponse error (no stack traces / default error page leaked).
A06 Vulnerable & Outdated ComponentsOK0 vulnerable packages (§1). One non-security runtime update available (Polly.Core).
A07 Identification & Auth FailuresN/AAPI is intentionally anonymous (public-read content). No credential/session handling to fail.
A08 Software & Data IntegrityOKWebhook payloads are HMAC-verified before mutating the slug allow-list.
A09 Logging & MonitoringOKStructured logging + observability (Application Insights wiring); no secrets logged.
A10 SSRFOKOutbound calls target fixed Contentful hosts only; the slug allow-list bounds what can be fetched — arbitrary/unknown slugs never trigger an upstream request.
